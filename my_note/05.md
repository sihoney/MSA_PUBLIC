# GITHUB_TOKEN, GHCR_TOKEN(PAT) 

좋다. 이건 그냥 “토큰 두 개”가 아니라
**CI/CD 권한 모델 이해의 핵심**이다. 여기서 제대로 잡자.

---

# 🔥 결론 먼저

> ✅ `GITHUB_TOKEN` = GitHub가 자동으로 만들어주는 “내부용 토큰”
> ✅ `GHCR_TOKEN` = 네가 직접 만든 “외부용/커스텀 토큰(PAT)”

---

# 📊 차이 한 번에 정리

| 구분    | GITHUB_TOKEN            | GHCR_TOKEN (PAT)   |
| ----- | ----------------------- | ------------------ |
| 생성    | 자동 생성                   | 직접 생성              |
| 관리    | GitHub가 자동              | 사용자가 관리            |
| 사용 범위 | 해당 repo 내부              | 여러 repo / 외부까지 가능  |
| 권한 설정 | workflow의 `permissions` | 생성 시 scope 직접 선택   |
| 보안    | 안전 (짧은 수명)              | 상대적으로 위험 (유출 시 위험) |
| 주 용도  | CI/CD 내부 작업             | 외부 시스템 / 복잡한 권한    |

---

# 🔥 1️⃣ GITHUB_TOKEN

## ✔️ 정체

👉 GitHub Actions 실행할 때 자동으로 생김

```yaml
password: ${{ secrets.GITHUB_TOKEN }}
```

👉 사실 secrets에 저장된 게 아니라
👉 **런타임에 자동 생성되는 토큰**

---

## ✔️ 특징

* 해당 repo에서만 사용 가능
* workflow 끝나면 사라짐 (짧은 수명)
* 권한은 여기서 제어:

```yaml
permissions:
  packages: write
```

---

## ✔️ 언제 쓰냐

👉 거의 90% 경우 이걸 써야 함

* GHCR push
* repo access
* issue/PR 작업

---

## ✔️ 장점

👉 관리할 필요 없음
👉 보안 안전
👉 실수 적음

---

# 🔥 2️⃣ GHCR_TOKEN (PAT, Personal Access Token)

## ✔️ 정체

👉 네가 직접 만든 Personal Access Token

GitHub → Settings → Developer settings → Tokens

---

## ✔️ 특징

* 여러 repo 접근 가능
* 외부에서도 사용 가능
* 권한(scope) 직접 설정

---

예:

* write:packages
* read:packages

---

## ✔️ 언제 쓰냐

👉 이런 경우에만 필요

* 다른 repo 이미지 push
* 외부 서버에서 ghcr pull
* 조직 간 권한 공유
* Actions 밖에서 사용

---

## ❗ 단점

👉 유출되면 위험
👉 권한 관리 귀찮음
👉 scope 실수하면 에러남 (지금 너 상황)

---

# 🔥 핵심 차이 (진짜 중요)

## GITHUB_TOKEN

👉 **"이 workflow 안에서만 쓰는 임시 열쇠"**

---

## GHCR_TOKEN

👉 **"네가 만든 만능 열쇠 (하지만 위험)"** 

---

# 🔥 지금 너 상황 분석

너 에러:

```text
permission_denied
```

👉 이유:

* GHCR_TOKEN 권한 부족
* 또는 잘못된 토큰

---

## 💡 해결이 GITHUB_TOKEN인 이유

```yaml
permissions:
  packages: write
```

👉 이미 권한 있음

👉 그래서 그냥:

```yaml
password: ${{ secrets.GITHUB_TOKEN }}
```

👉 이게 가장 안전하고 확실

---

# 🔥 실무 기준 (중요)

👉 내가 단호하게 말해준다:

> ❗ CI/CD에서 GHCR_TOKEN 거의 안 쓴다

---

## ✔️ 기본 원칙

* 같은 repo → GITHUB_TOKEN
* 외부/복잡 → PAT

---

# 🧠 너 수준에서 꼭 기억해야 할 것

👉 “토큰 문제 생기면 무조건 scope부터 의심”

---

# 💬 한 줄 정리

👉 **GITHUB_TOKEN = 자동, 안전, 기본값**
👉 **GHCR_TOKEN = 수동, 위험, 특별한 경우만**

---

# 🚀 다음 단계 추천

여기까지 이해했으면 다음은 이거다:

👉 “GHCR 이미지 push → pull → docker run 흐름”
👉 “CI → CD로 이어지는 실제 배포 구조”

이거 연결하면 너 CI/CD 제대로 이해한 수준 된다.
