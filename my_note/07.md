# GITHUB vs PAT, MSA 환경에서 무엇을 사용

좋다. 이건 헷갈릴 수밖에 없는 부분인데, **한 번에 머리에 들어오게 정리해줄게.**

---

# 🔥 핵심 한 줄

> 👉 **GITHUB_TOKEN = “GitHub 안에서만 쓰는 자동 열쇠”**
> 👉 **PAT = “밖에서도 쓰는 내가 만든 열쇠”**

---

# 🧠 직관적으로 이해 (비유)

## 🏢 GITHUB_TOKEN

👉 회사 건물 안에서만 쓰는 **출입카드**

* 회사(GitHub)가 자동으로 발급
* 건물 안(repo)에서만 사용 가능
* 퇴근하면(워크플로 끝나면) 사라짐

---

## 🔑 PAT

👉 집 + 회사 + 외부 어디서든 쓰는 **내 개인 열쇠**

* 내가 직접 만듦
* 어디서든 사용 가능 (로컬, 서버 등)
* 계속 살아있음 (유출되면 위험)

---

# 📊 차이 한 번에 정리

| 구분    | GITHUB_TOKEN      | PAT      |
| ----- | ----------------- | -------- |
| 생성    | 자동                | 직접 생성    |
| 사용 위치 | GitHub Actions 내부 | 어디서든     |
| 수명    | 짧음 (job 끝나면 끝)    | 길게 유지    |
| 보안    | 안전                | 관리 잘해야 함 |
| 권한    | workflow에서 설정     | 생성할 때 설정 |

---

# 🔥 언제 뭘 써야 하냐 (이게 진짜 중요)

## ✅ 1️⃣ GitHub Actions 안에서

👉 무조건 이거

```yaml
secrets.GITHUB_TOKEN
```

👉 이유:

* 자동
* 안전
* 권한 충분 (packages: write만 주면 됨)

---

## ✅ 2️⃣ 내 로컬 PC에서 docker pull

👉 PAT 필요

```bash
docker login ghcr.io
```

👉 여기서 GITHUB_TOKEN 못 씀

---

## ✅ 3️⃣ EC2 / 서버에서 배포할 때

👉 PAT 필요

---

# 🔥 MSA 기준으로 보면 (너한테 핵심)

## 🎯 상황 나눠서 보자

---

## 💡 1단계 (지금 너 상태)

* GitHub Actions → 이미지 빌드 → GHCR push

👉 ✔️ GITHUB_TOKEN만 사용

---

## 💡 2단계 (CD 붙이면)

* 서버 (EC2 / Kubernetes)가
* GHCR에서 이미지 pull

👉 ✔️ 여기서 PAT 필요

---

## 💡 구조로 보면

```text
[GitHub Actions]
  ↓ (push)
GHCR (이미지 저장소)
  ↓ (pull)
[서버 / Kubernetes]
```

---

## 👉 정리하면

| 위치                  | 사용하는 토큰      |
| ------------------- | ------------ |
| CI (GitHub Actions) | GITHUB_TOKEN |
| CD (서버)             | PAT          |

---

# 🔥 왜 이렇게 나누냐 (중요)

## GITHUB_TOKEN

👉 GitHub 내부에서만 작동

---

## 서버 (외부)

👉 GitHub가 모르는 환경

👉 그래서 직접 인증 필요 → PAT

---

# 🔥 실무 기준 결론

👉 내가 단호하게 정리해준다:

* CI → GITHUB_TOKEN
* CD → PAT

---

# 💬 한 줄 정리

👉 **“GitHub 안이면 GITHUB_TOKEN, 밖이면 PAT”**
