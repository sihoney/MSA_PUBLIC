# GITHUB_ENV, GITHUB_OUTPUT

---

## 🔥 핵심 결론

> ✅ 둘 다 “값 공유” 맞다
> ❗ 하지만 **공유 범위와 목적이 완전히 다르다**

---

# 📊 차이 한 방에 정리

| 구분    | GITHUB_ENV      | GITHUB_OUTPUT                 |
| ----- | --------------- | ----------------------------- |
| 목적    | 환경변수 공유         | step 결과값 전달                   |
| 사용 범위 | 같은 job의 모든 step | 특정 step → 다른 step             |
| 접근 방식 | `$VAR`          | `${{ steps.id.outputs.xxx }}` |
| 사용 위치 | run 내부          | workflow 레벨 표현식               |

---

# 🔥 1️⃣ GITHUB_ENV

## ✔️ 역할

👉 **환경변수 저장소**

```bash
echo "HELLO=world" >> $GITHUB_ENV
```

👉 이후 step에서:

```bash
echo $HELLO
```

👉 사용 가능

---

## ✔️ 특징

* 쉘 환경처럼 사용
* 그냥 변수처럼 씀 (`$HELLO`)
* 같은 job 안에서만 공유됨

---

## ✔️ 느낌

👉 “전역 변수” 느낌

---

# 🔥 2️⃣ GITHUB_OUTPUT

## ✔️ 역할

👉 **step의 결과값을 외부로 노출**

```bash
echo "image=ghcr.io/..." >> $GITHUB_OUTPUT
```

👉 다음 step에서:

```yaml
${{ steps.prepare-image.outputs.image }}
```

---

## ✔️ 특징

* 반드시 `id` 있어야 함

```yaml
- id: prepare-image
```

* `${{ }}` 문법으로 접근

---

## ✔️ 느낌

👉 “함수 return 값” 느낌

---

# 💡 진짜 중요한 차이 (이게 핵심이다)

## 👉 GITHUB_ENV

```bash
echo "A=1" >> $GITHUB_ENV
```

👉 그냥 쉘 변수

---

## 👉 GITHUB_OUTPUT

```bash
echo "result=1" >> $GITHUB_OUTPUT
```

👉 이건 쉘 변수가 아니라

👉 **workflow DSL에서 쓰는 값**

---

# 🔥 예제로 보면 바로 이해됨

## ENV

```yaml
- run: echo "NAME=jiyeon" >> $GITHUB_ENV

- run: echo $NAME
```

👉 출력됨

---

## OUTPUT

```yaml
- id: test
  run: echo "value=hello" >> $GITHUB_OUTPUT

- run: echo "${{ steps.test.outputs.value }}"
```

👉 출력됨

---

# 🚨 중요한 오해 바로잡기

너가 말한 것 👇

> "둘 다 RUNNER의 특정 JOB 실행 환경에서 값을 공유하기 위해 존재?"

👉 절반만 맞다

---

## ✔️ GITHUB_ENV

👉 맞음 (환경 공유)

---

## ❗ GITHUB_OUTPUT

👉 ❌ 단순 공유 아님

👉 **step → workflow 레벨 전달용**

---

# 🔥 왜 두 개로 나눴냐 (실무 포인트)

이게 진짜 중요하다 👇

---

## GITHUB_ENV만 쓰면 안 되는 이유

```bash
echo "IMAGE=xxx" >> $GITHUB_ENV
```

👉 docker action 같은 곳에서 못 씀

---

## GITHUB_OUTPUT 필요한 이유

```yaml
with:
  tags: ${{ steps.prepare-image.outputs.image }}
```

👉 이건 쉘 변수로는 못 함

---

# 🧠 구조로 보면 이렇게 된다

```
run (bash)
  ↓
GITHUB_ENV → 쉘 변수
  ↓
GITHUB_OUTPUT → workflow 변수
  ↓
YAML expression (${{ }})
```

---

# 🔥 한 줄 핵심 정리

👉 **ENV = 쉘 변수 공유**
👉 **OUTPUT = step 결과를 workflow에서 쓰기 위한 값**

---

# 💬 너한테 중요한 포인트 (진짜 실무)

지금 너 수준에서 반드시 기억해야 할 거:

👉 docker build / push / tag 같은 데서

* ENV → 내부 계산용
* OUTPUT → 다음 step 전달용

---

# 🚀 다음 단계 (여기까지 이해했으면)

이거 이어서 보면 완전히 끝난다:

👉 "OUTPUT → docker/build-push-action에서 실제로 어떻게 쓰이는지"
👉 "multi-tag (latest + sha) 왜 같이 쓰는지"

원하면 바로 이어서 잡아줄게.
